PART 1: CLASS RELATIONSHIPS (SEPARATED BY RELATIONSHIP TYPE)
================================================================================

--------------------------------------------------------------------------------
1. INHERITANCE (Generalization / "IS-A" & Interface Realization)
--------------------------------------------------------------------------------
Definition: A subclass inherits attributes, methods, and contracts from an
abstract superclass or interface.

A) Model Layer Inheritance (extends BaseEntity):
   - User       ──▷ BaseEntity   (User IS-A BaseEntity)
   - Room       ──▷ BaseEntity   (Room IS-A BaseEntity)
   - Booking    ──▷ BaseEntity   (Booking IS-A BaseEntity)
   - Review     ──▷ BaseEntity   (Review IS-A BaseEntity)
   - PromoCode  ──▷ BaseEntity   (PromoCode IS-A BaseEntity)
   * Details: All 5 domain entities inherit 'id' (Long), 'createdAt' (LocalDateTime),
     getters/setters, and override the abstract 'validate()' method from BaseEntity.

B) Service Layer Inheritance (extends BaseService<T>):
   - UserService       ──▷ BaseService<User>
   - RoomService       ──▷ BaseService<Room>
   - BookingService    ──▷ BaseService<Booking>
   - ReviewService     ──▷ BaseService<Review>
   - PromoCodeService  ──▷ BaseService<PromoCode>
   * Details: All 5 services inherit generic CRUD operations ('getAll()',
     'findById()', 'getById()', 'save()', 'delete()') from BaseService<T>.

C) Controller Layer Inheritance (extends BaseController):
   - AuthController    ──▷ BaseController
   - RoomController    ──▷ BaseController
   - BookingController ──▷ BaseController
   - ReviewController  ──▷ BaseController
   - PromoController   ──▷ BaseController
   - AdminController   ──▷ BaseController
   * Details: All 6 REST controllers inherit centralized exception handling
     ('handleBadRequest()', 'handleServerError()') and ID parsing ('parseId()').

D) Repository & Configuration Interface Inheritance / Realization:
   - UserRepository      ──▷ JpaRepository<User, Long>
   - RoomRepository      ──▷ JpaRepository<Room, Long>
   - BookingRepository   ──▷ JpaRepository<Booking, Long>
   - ReviewRepository    ──▷ JpaRepository<Review, Long>
   - PromoCodeRepository ──▷ JpaRepository<PromoCode, Long>
   - DataInitializer     ..▷ CommandLineRunner (implements run())
   - WebConfig           ..▷ WebMvcConfigurer  (implements addCorsMappings())


--------------------------------------------------------------------------------
2. ASSOCIATION ("USES-A" / Structural Link Between Independent Domain Classes)
--------------------------------------------------------------------------------
Definition: A structural relationship where objects of one class are connected
to objects of another class, and both have independent lifecycles.

   - Booking (Many) ──────> (1) Room
     * Type: Unidirectional Many-to-One Association (@ManyToOne)
     * Details: 'Booking' holds a reference 'private Room room' (foreign key
       'room_id'). Multiple bookings can reference the same Room category, and
       the Room exists independently of any individual Booking.

   - Booking (Many) ──────> (1) User
     * Type: Unidirectional Association (via 'private Long userId')
     * Details: Links a reservation to the registered guest who placed it.

   - BookingService (1) ──────> (1) RoomService
     * Type: Service-to-Service Association
     * Details: 'BookingService' collaborates with 'RoomService' to look up
       rooms by ID/slug and refresh room availability after booking creation.


--------------------------------------------------------------------------------
3. AGGREGATION ("HAS-A" / Shared Ownership - Weak Lifecycle Dependency)
--------------------------------------------------------------------------------
Definition: A "whole-part" relationship where the parent class holds a reference
to a child object injected from outside (Dependency Injection). If the parent
is destroyed, the injected collaborator still exists independently.

A) Controllers Aggregating Services:
   - AuthController    ◇────── UserService
   - RoomController    ◇────── RoomService
   - BookingController ◇────── BookingService
   - ReviewController  ◇────── ReviewService
   - PromoController   ◇────── PromoCodeService
   - AdminController   ◇────── UserService, RoomService, BookingService, ReviewService

B) Services Aggregating Repositories:
   - BaseService<T>    ◇────── JpaRepository<T, Long>
   - UserService       ◇────── UserRepository
   - RoomService       ◇────── RoomRepository, BookingRepository
   - BookingService    ◇────── BookingRepository
   - ReviewService     ◇────── ReviewRepository
   - PromoCodeService  ◇────── PromoCodeRepository

C) Data Seeder Aggregating Repositories:
   - DataInitializer   ◇────── RoomRepository, UserRepository, ReviewRepository,
                               PromoCodeRepository, BookingRepository


--------------------------------------------------------------------------------
4. COMPOSITION ("PART-OF" / Strong Ownership - Dependent Lifecycle)
--------------------------------------------------------------------------------
Definition: A strong "whole-part" relationship where the contained part cannot
exist meaningfully outside its owning class and shares the owner's lifecycle.

   - BookingRequest ◆────── GuestInfoDto
     * Details: 'BookingRequest' contains 'private GuestInfoDto guestInfo'. The
       guest info payload is created and destroyed as part of the booking request.

   - Room ◆────── List<String> amenities & List<String> images (@ElementCollection)
     * Details: Stored in dependent collection tables ('room_amenity_names' and
       'room_image_urls'). Their lifecycle is strictly bound to the owning 'Room'.

   - User ◆────── List<String> savedRoomIds (@ElementCollection)
     * Details: Stored in the dependent collection table ('user_saved_rooms').
       Exists only as part of the owning 'User' entity.

   - Booking ◆────── Guest Snapshot & Financial Breakdown
     * Details: Guest details ('guestFullName', 'guestEmail', 'guestPhone',
       'guestNicPassport') and invoice totals are composed directly inside the
       'Booking' record and exposed as a composed map via 'getGuestInfo()'.


--------------------------------------------------------------------------------
5. DEPENDENCY ("DEPENDS-ON" / Transient Method Parameter or Return Usage)
--------------------------------------------------------------------------------
Definition: A weaker "uses" relationship where a class temporarily uses another
class as a method parameter, local variable, or return type without storing it
as a permanent field.

   - AuthController    - - -> AuthRequest, RegisterRequest, UpdateProfileRequest, User
   - UserService       - - -> RegisterRequest, UpdateProfileRequest, User, HttpClient
   - RoomController    - - -> Room
   - RoomService       - - -> Room, Booking
   - Room              - - -> Booking (used in 'updateAvailability(List<Booking>)')
   - BookingController - - -> BookingRequest, CancelBookingRequest, RateBookingRequest, Booking
   - BookingService    - - -> BookingRequest, GuestInfoDto, Booking, Room
   - ReviewController  - - -> ReviewRequest, Review
   - ReviewService     - - -> ReviewRequest, Review
   - PromoController   - - -> PromoValidateRequest, PromoCode
   - PromoCodeService  - - -> PromoCode
   - AdminController   - - -> User, Room, Booking, Review
