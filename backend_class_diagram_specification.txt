1. ARCHITECTURAL OVERVIEW & LAYERED PATTERN
====================================================================================================
The backend follows a classic layered Domain-Driven Spring Boot enterprise architecture:

  [Client / Web Browser / Mobile App]
                 |  HTTP REST Calls / JSON
                 v
  +-------------------------------------------------------------+
  |                   CONTROLLER LAYER                          |
  | (BaseController, AuthController, RoomController,            |
  |  BookingController, PromoController, ReviewController,      |
  |  AdminController, MainController)                           |
  +-------------------------------------------------------------+
                 |  Calls Business Operations / Passes DTOs
                 v
  +-------------------------------------------------------------+
  |                     SERVICE LAYER                           |
  | (BaseService<T>, UserService, RoomService,                  |
  |  BookingService, PromoCodeService, ReviewService)           |
  +-------------------------------------------------------------+
                 |  Invokes CRUD & Domain Queries
                 v
  +-------------------------------------------------------------+
  |                   REPOSITORY LAYER                          |
  | (UserRepository, RoomRepository, BookingRepository,         |
  |  PromoCodeRepository, ReviewRepository) -> JpaRepository    |
  +-------------------------------------------------------------+
                 |  Hydrates / Persists Entities
                 v
  +-------------------------------------------------------------+
  |                     DOMAIN MODEL LAYER                      |
  | (BaseEntity, User, Room, Booking, PromoCode, Review)        |
  +-------------------------------------------------------------+
                 |  Object-Relational Mapping (Hibernate/JPA)
                 v
  +-------------------------------------------------------------+
  |                      DATABASE (MySQL)                       |
  +-------------------------------------------------------------+

+------------------+---------------+--------------------+-------------------------------------------+
| Relationship     | UML Symbol    | PlantUML / Mermaid | Precise Semantics in this Backend         |
+------------------+---------------+--------------------+-------------------------------------------+
| Inheritance      | Triangle Head | --|>               | "is-a" relationship (Subclass extends     |
| (Generalization) | Solid line    |                    | Superclass, e.g. User extends BaseEntity). |
+------------------+---------------+--------------------+-------------------------------------------+
| Realization      | Triangle Head | ..|>               | Class implements an interface contract    |
| (Implementation) | Dashed line   |                    | (e.g. Repository extends JpaRepository).  |
+------------------+---------------+--------------------+-------------------------------------------+
| Composition      | Filled Diamond| *--                | "owns-a" strict lifecycle dependency. If  |
|                  | Solid line    |                    | parent is deleted, parts die (e.g. Room   |
|                  |               |                    | owns @ElementCollection amenities/images).|
+------------------+---------------+--------------------+-------------------------------------------+
| Aggregation      | Open Diamond  | o--                | "has-a" shared lifecycle. Part can exist  |
|                  | Solid line    |                    | independently (e.g. Booking has Room, or  |
|                  |               |                    | Service aggregates injected Repository).  |
+------------------+---------------+--------------------+-------------------------------------------+
| Association      | Simple arrow  | --> or --          | Structural reference between two classes  |
|                  | Solid line    |                    | with defined multiplicity (e.g. User and  |
|                  |               |                    | Booking association).                     |
+------------------+---------------+--------------------+-------------------------------------------+
| Dependency       | Arrow head    | ..>                | "uses-a" transient relation (e.g. Method  |
|                  | Dashed line   |                    | takes a DTO as parameter or returns it).  |
+------------------+---------------+--------------------+-------------------------------------------+

4. EXHAUSTIVE RELATIONSHIP CLASSIFICATION & MATRIX
====================================================================================================

----------------------------------------------------------------------------------------------------
4.1 INHERITANCE (GENERALIZATION: Subclass --|> Superclass)
----------------------------------------------------------------------------------------------------
Definition: Strong object-oriented specialization where child classes inherit properties and behaviors.

1. User --|> BaseEntity
   - User extends BaseEntity. Inherits 'id', 'createdAt', and implements abstract 'validate()'.
2. Room --|> BaseEntity
   - Room extends BaseEntity. Inherits 'id', 'createdAt', and implements abstract 'validate()'.
3. Booking --|> BaseEntity
   - Booking extends BaseEntity. Inherits 'id', 'createdAt', and implements abstract 'validate()'.
4. PromoCode --|> BaseEntity
   - PromoCode extends BaseEntity. Inherits 'id', 'createdAt', and implements abstract 'validate()'.
5. Review --|> BaseEntity
   - Review extends BaseEntity. Inherits 'id', 'createdAt', and implements abstract 'validate()'.

6. UserService --|> BaseService<User>
   - UserService extends generic BaseService parameterized with User.
7. RoomService --|> BaseService<Room>
   - RoomService extends generic BaseService parameterized with Room.
8. BookingService --|> BaseService<Booking>
   - BookingService extends generic BaseService parameterized with Booking.
9. PromoCodeService --|> BaseService<PromoCode>
   - PromoCodeService extends generic BaseService parameterized with PromoCode.
10. ReviewService --|> BaseService<Review>
   - ReviewService extends generic BaseService parameterized with Review.

11. AuthController --|> BaseController
   - AuthController inherits common exception handlers and parseId() helper.
12. RoomController --|> BaseController
   - RoomController inherits common exception handlers and parseId() helper.
13. BookingController --|> BaseController
   - BookingController inherits common exception handlers and parseId() helper.
14. PromoController --|> BaseController
   - PromoController inherits common exception handlers and parseId() helper.
15. ReviewController --|> BaseController
   - ReviewController inherits common exception handlers and parseId() helper.
16. AdminController --|> BaseController
   - AdminController inherits common exception handlers and parseId() helper.


----------------------------------------------------------------------------------------------------
4.2 REALIZATION (INTERFACE IMPLEMENTATION: Class ..|> Interface)
----------------------------------------------------------------------------------------------------
Definition: A class or interface realizes the operations defined by an interface.

1. UserRepository ..|> JpaRepository<User, Long>
   - UserRepository interface extends Spring Data JpaRepository.
2. RoomRepository ..|> JpaRepository<Room, Long>
   - RoomRepository interface extends Spring Data JpaRepository.
3. BookingRepository ..|> JpaRepository<Booking, Long>
   - BookingRepository interface extends Spring Data JpaRepository.
4. PromoCodeRepository ..|> JpaRepository<PromoCode, Long>
   - PromoCodeRepository interface extends Spring Data JpaRepository.
5. ReviewRepository ..|> JpaRepository<Review, Long>
   - ReviewRepository interface extends Spring Data JpaRepository.

6. DataInitializer ..|> CommandLineRunner
   - DataInitializer implements CommandLineRunner interface to execute database seed logic on startup.
7. WebConfig ..|> WebMvcConfigurer
   - WebConfig implements WebMvcConfigurer interface to customize CORS mapping.


----------------------------------------------------------------------------------------------------
4.3 COMPOSITION (STRONG PART-WHOLE: Parent *-- Child)
----------------------------------------------------------------------------------------------------
Definition: The child belongs exclusively to the parent; the child's lifecycle is bound to the parent.
If parent entity is deleted, child records are cascaded or destroyed.

1. Room (1) *-- (0..*) Amenity [Table: room_amenity_names]
   - Room owns its list of amenity names (@ElementCollection, @CollectionTable). They cannot exist without Room.
2. Room (1) *-- (0..*) ImageUrl [Table: room_image_urls]
   - Room owns its list of image URLs (@ElementCollection, @CollectionTable).
3. User (1) *-- (0..*) SavedRoomId [Table: user_saved_rooms]
   - User owns its list of saved room IDs (@ElementCollection, @CollectionTable).
4. BookingRequest (1) *-- (1) GuestInfoDto
   - BookingRequest contains GuestInfoDto as an integral, inseparable nested value object.
5. UserService (1) *-- (1) HttpClient
   - UserService instantiates and owns its internal java.net.http.HttpClient instance for ImgBB API uploads.


----------------------------------------------------------------------------------------------------
4.4 AGGREGATION (WEAK PART-WHOLE / DEPENDENCY INJECTION: Whole o-- Part)
----------------------------------------------------------------------------------------------------
Definition: A "has-a" relationship where the parts exist independently of the whole.
In Spring Boot, constructor-injected beans represent architectural Aggregations.

1. Booking (0..*) o-- (1) Room
   - In JPA: @ManyToOne @JoinColumn(name="room_id"). Booking holds a Room reference. If a Booking is deleted,
     the Room still exists. Multiplicity: Room 1 holds 0..* Bookings.
2. BaseService (1) o-- (1) JpaRepository<T, Long>
   - BaseService has-a reference to repository.
3. UserService (1) o-- (1) UserRepository
   - Injected via constructor.
4. RoomService (1) o-- (1) RoomRepository
   - Injected via constructor.
5. RoomService (1) o-- (1) BookingRepository
   - Injected via constructor to calculate room availability.
6. BookingService (1) o-- (1) BookingRepository
   - Injected via constructor.
7. BookingService (1) o-- (1) RoomService
   - BookingService delegates room validation and inventory checks to RoomService.
8. PromoCodeService (1) o-- (1) PromoCodeRepository
   - Injected via constructor.
9. ReviewService (1) o-- (1) ReviewRepository
   - Injected via constructor.
10. AuthController (1) o-- (1) UserService
   - Injected via constructor.
11. RoomController (1) o-- (1) RoomService
   - Injected via constructor.
12. BookingController (1) o-- (1) BookingService
   - Injected via constructor.
13. PromoController (1) o-- (1) PromoCodeService
   - Injected via constructor.
14. ReviewController (1) o-- (1) ReviewService
   - Injected via constructor.
15. AdminController (1) o-- (1) UserService
16. AdminController (1) o-- (1) RoomService
17. AdminController (1) o-- (1) BookingService
18. AdminController (1) o-- (1) ReviewService
19. DataInitializer (1) o-- (1) RoomRepository
20. DataInitializer (1) o-- (1) UserRepository
21. DataInitializer (1) o-- (1) ReviewRepository
22. DataInitializer (1) o-- (1) PromoCodeRepository
23. DataInitializer (1) o-- (1) BookingRepository


----------------------------------------------------------------------------------------------------
4.5 ASSOCIATION (STRUCTURAL NAVIGABILITY: Source --> Target)
----------------------------------------------------------------------------------------------------
Definition: A structural link between two independent entities or classes.

1. User (1) ---- (0..*) Booking
   - Conceptual Association: A User places zero or more Bookings.
   - Mechanism: Booking stores `userId: Long` and `guestEmail: String`.
   - Navigability: BookingRepository queries `findByUserIdOrderByCreatedAtDesc(userId)`.
2. Booking (0..*) ---- (0..1) PromoCode
   - Conceptual Association: A Booking applies an optional PromoCode.
   - Mechanism: Booking stores `promoCodeApplied: String`.
3. Room (1) ---- (0..*) Booking
   - Conceptual Bidirectional: Booking references Room directly via `@ManyToOne`. Room enriches its runtime
     availability through `updateAvailability(List<Booking>)`.


----------------------------------------------------------------------------------------------------
4.6 DEPENDENCY (USAGE / PARAMETER PASSING: Client ..> Supplier)
----------------------------------------------------------------------------------------------------
Definition: "uses-a" relationship where a class depends on another via method signatures, local variables,
or return types. Changes to the supplier may impact the client.

1. AuthController ..> AuthRequest (Method parameter in login())
2. AuthController ..> RegisterRequest (Method parameter in register())
3. AuthController ..> UpdateProfileRequest (Method parameter in updateProfile())
4. UserService ..> RegisterRequest (Method parameter in register())
5. UserService ..> UpdateProfileRequest (Method parameter in updateProfile())
6. BookingController ..> BookingRequest (Method parameter in createBooking())
7. BookingController ..> CancelBookingRequest (Method parameter in cancelBooking())
8. BookingController ..> RateBookingRequest (Method parameter in rateBooking())
9. BookingService ..> BookingRequest (Method parameter in createBooking())
10. BookingService ..> GuestInfoDto (Extracted from BookingRequest)
11. PromoController ..> PromoValidateRequest (Method parameter in validate())
12. ReviewController ..> ReviewRequest (Method parameter in createReview())
13. ReviewService ..> ReviewRequest (Method parameter in createReview())
14. HotelReservationApplication ..> SpringApplication (Bootstrap dependency)
15. AppReadyListener ..> ApplicationReadyEvent (Event listener dependency)
